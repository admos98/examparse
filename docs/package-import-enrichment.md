# Package import and enrichment

Batch import runs in two sequential stages: import each subfolder, then explain and judge each newly imported exam. Duplicate packages are not enriched again. Choose **Import only** to skip the second stage. Each stage reports its status independently; a failure on one exam does not prevent later exams from running.

Listening collateral is divided by `## Section N` headings. An explicit section/group reference wins over a heading's question range; ambiguous or missing mappings are left unassigned. The package receipt records the section (or null) per listening label. A legacy imported `script` without a mapping receipt is not used during re-enrichment: the original package and scripts must be imported again to establish trustworthy mappings. Re-import skips duplicates, so back up and remove the old library entry first if you need to replace it; old verdicts are not silently rewritten. A transcript supplied directly on a listening question remains usable as question-specific evidence.

Full package labels identify questions; numeric `no` is only the base number. Optional groups carry their member labels, branch membership and rule in the structured document. Point totals use the printed group total when available, otherwise one branch (or one choice per number), not both alternatives. Groups require an announced rule or shared instruction and matching labels; unannounced alternatives are not inferred from subject matter.

Explanation generation uses batches of at most four within an instruction group, salvages valid responses and retries each missing item once. The final notes report coverage. In the structured export, uncertain model explanations remain with their check state; rejected explanations are suppressed. The student-facing Appendix A bank export includes model explanations only when verified, and omits uncertain, unjudged and rejected explanations. Both exports derive `answer_key_needs_review` and `manual_review` from saved verdicts and preserve existing tags, so re-export needs no model calls. Coverage notes are outcome-first ("explanations: 60 of 63 keyed; 2 rejected by the checker"); intermediate malformed/retry narration appears only when the final outcome is incomplete, as a single counted summary line.

## Sample answers and rubrics (#57)

Keyless descriptive items (short answer, paragraph, essay, imported `long_answer`/writing types) receive a model sample answer and a 2–4 criterion rubric (maxPoints summing to the item's points) in the same explain-stage batching. The decision judge grades each with its single clause at the standard thresholds: verified (bank + structured), uncertain (structured only), rejected (record-only, suppressed everywhere). Step 4 shows "model sample + rubric proposed — confirm or edit"; the item keeps the `needs_rubric` tag until the teacher confirms or edits, which stores the artifacts as teacher-confirmed and clears the tag. Nothing about grading behaviour changes before that click. Descriptive types export to the bank as `long_answer`; missing artifacts never block an export.

## Proposals never become keys (#57)

A keyless auto-graded item may receive a checker proposal, stored only as `enrichment.proposedAnswer` and shown in the attention list. It is never written to any executable grading field — exports are byte-identical with and without it. The Step 4 adopt button pre-fills the key editor; the teacher's save stores the key as teacher-entered and marks the proposal adopted. Until then the item stays keyless downstream and carries `answer_key_needs_review`. Questions whose pixels are unavailable keep the evidence gate and receive no proposal.

## Images travel (#57)

Placeholder tokens in package stems (`img_<sha>`, `img_<sha>stem`, `assets/<sha>.<ext>`) are resolved at import: the asset attaches at the token offset, the token leaves the stem, and an unresolved token becomes an explicit warning flag. Step 4 renders the actual image and never the token. The bank export writes Appendix A v1.1: SHA-256-named files under `assets/`, an asset manifest (id → file, sha, mime, byte size), hash-only stem references, and one pooled file per shared asset referenced by each owner. Missing pixels produce an explicit `missing:<sha>` marker plus a report entry, never a silent token or a failed export. The report counts `images_placed` and `image_references` truthfully.

## Attention-first review, inheritance and provenance (#57)

Step 4 opens on **Needs attention**: disagreements, uncertains, keyless items (tashrihi awaiting confirmation; auto-graded keyless with/without proposal), image mismatches and rejected explanations, grouped in that order; the header count and the visible list are the same set. Quiet items collapse into one "N verified · show" line, expandable and searchable. Questions are identified by label everywhere. Completeness probability displays only when its flag fired; confidence falls back verification → demand → null. Each factored passage is judged once; abstained members inherit its confident lesson as `curriculumSource: "inherited"` without overriding teacher or confident individual votes. Bank `source_ref` is the compact `<file> · p.<page> · item <label> · group <n> (<total>)` form (≤200 chars); prose refs stay structured-only and `source_type` values are never remapped.

## Field protocol (feature freeze gate)

After unit acceptance, a closing batch is done only when a parent folder of **previously unseen** real exams (not the tuning packages) runs batch-import → chain-enrich unattended with: (a) zero wrong-evidence verdicts on a script spot-check, (b) the attention screen fitting one readable list, (c) every picture-referencing bank question carrying its asset file in the zip, and (d) the export passing the downstream bank adapter/`validateImportBatch` with only expected-state notes (keyless tashrihi as `needs_rubric`, no rejections). Attach the run's results to the PR. After that, the import/enrichment product is feature-frozen: new work requires a field report from real usage.
