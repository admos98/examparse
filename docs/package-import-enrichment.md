# Package import and enrichment

Batch import runs in two sequential stages: import each subfolder, then explain and judge each newly imported exam. Duplicate packages are not enriched again. Choose **Import only** to skip the second stage. Each stage reports its status independently; a failure on one exam does not prevent later exams from running.

Listening collateral is divided by `## Section N` headings. An explicit section/group reference wins over a heading's question range; ambiguous or missing mappings are left unassigned. The package receipt records the section (or null) per listening label. A legacy imported `script` without a mapping receipt is not used during re-enrichment: the original package and scripts must be imported again to establish trustworthy mappings. Re-import skips duplicates, so back up and remove the old library entry first if you need to replace it; old verdicts are not silently rewritten. A transcript supplied directly on a listening question remains usable as question-specific evidence.

Full package labels identify questions; numeric `no` is only the base number. Optional groups carry their member labels, branch membership and rule in the structured document. Point totals use the printed group total when available, otherwise one branch (or one choice per number), not both alternatives. Groups require an announced rule or shared instruction and matching labels; unannounced alternatives are not inferred from subject matter.

Explanation generation uses batches of at most four within an instruction group, salvages valid responses and retries each missing item once. The final notes report coverage. In the structured export, uncertain model explanations remain with their check state; rejected explanations are suppressed. The student-facing Appendix A bank export includes model explanations only when verified, and omits uncertain, unjudged and rejected explanations. Both exports derive `answer_key_needs_review` and `manual_review` from saved verdicts and preserve existing tags, so re-export needs no model calls.
